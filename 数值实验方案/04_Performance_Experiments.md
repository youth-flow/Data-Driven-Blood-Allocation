# DAT Synthetic 性能实验协议：P1、P2、P3

> **文档状态**：性能实验实施规范（2026-11-04 整理版）  
> **依据**：最初 `synthetic_protocol.md` 第 1–4、6–8 节及本轮已确认的评价口径。  
> **实验边界**：**只做 Synthetic，不包含医院真实数据实验，也不伪造医院历史收货策略**。  
> **最终评价指标严格只有两个**：**平均运营成本（Average Cost, `AC`）**和**期末库存达到目标 \(G\) 的服务率（Target Service Level, `SL_G`）**。其他量只允许作为训练控制、实现元数据或内部合法性检查，**不得再作为 P1–P3 的性能指标**。

## 1. 研究目标和实验总体结构

一个决策日中，血液中心事前观察 \(Z=(A,X)\)，选择补充量 \(q\ge0\)。需求 \(D\) 实现后，期末库存

\[
I_{\mathrm{end}}=I+q-D.
\]

运营目标是：**面对随机需求，尽量以较低成本让期末库存维持在目标 \(G\) 附近**。因此既需要度量偏离 \(G\) 造成的不对称成本，也需要报告达到 \(G\) 的频率。它不同于只考察患者需求是否被完全满足的服务率定义。

三组性能实验：

| 实验 | 主要比较因素 | 机制场景 | 唯一的结果指标 |
|---|---|---|---|
| **P1：基准比较** | DAT 与其他预测/决策方法 | **S1–S4** | `AC`, `SL_G` |
| **P2：DAT 结构消融** | Self-Attention、池化、日级 Query | **S2–S4** | `AC`, `SL_G` |
| **P3：信息价值** | L0–L4 可见信息等级 | **S1–S4** | `AC`, `SL_G` |

> **执行约定说明**：P1=S1–S4、P2=S2–S4 来自原协议；原始 MD 对 P3 场景未作明文指定。本版依据你后来确认的“性能三组随场景、\(\tau\)、\(G\) 评价”，将 **P3 固定为 S1–S4**。这是明确新增的**实验范围约定**，不是修改 DGP 生成机制。

## 2. DGP、\(\tau\)、\(G\) 和固定尺度

### 2.1 保留原始性能规模

| 变量 | 固定设置 |
|---|---|
| 决策前患者人数上界 \(M\) | **8** |
| 患者特征 \(d_a\) | 3（\(u_i,v_i,r_i\)） |
| 完整日级特征 | 8 维，包含 \(N/M\)、库存和群体摘要 |
| 需求上界 \(B\) | **36.5** |
| DAT 潜维 | **64** |
| 原库存机制 | \(I=315+20c_1+e_I,\ e_I\sim U(-70,70)\) |
| 原目标网格 | \(G\in\{260,280,300,320,340\}\) |
| DGP 场景 | S1、S2、S3、S4（仅概率机制不同） |
| 连续需求 | \(D=D_0+J,\ J\sim U(0,0.5)\) |

**不采用**任何曾讨论过的 \(I\) 和 \(G\) 低尺度替代方案；DAT 不读取真实医院历史数据。

### 2.2 两组运营环境变量的不同角色

主 \(\tau\) 网格：

\[
\boxed{\tau\in\{0.5,0.6,0.7,0.8,0.9\}.}
\]

\(\tau=0.95\) 为单独标识的尾部扩展，不混入五个主 \(\tau\) 的共同选择规则。

目标库存：

\[
\boxed{G\in\{260,280,300,320,340\}.}
\]

- 改变 \(\tau\)：改变 Pinball 预测任务以及成本中缺口/超额的相对权重。DAT **每个 \(\tau\) 独立训练**，不同 \(\tau\) 不共享权重、不做跨分位排序后处理。
- 改变 \(G\)：只改变部署时的补货计算和评价目标。**同一个已训练的 \(\tau\)-模型必须复用于全部五个 \(G\)**，不得按 \(G\) 重新训练模型。
- 改变 S1–S4：改变实际条件需求机制。应使用该场景对应的独立训练/验证/测试需求；同一个独立重复内可见输入 \((A,X,I)\) 在场景间配对保持一致。

因此完整性能结果是按

\[
\boxed{\mathrm{scenario}\times\tau\times G\times\mathrm{method}}
\]

索引的两项评价：\((\mathrm{AC},\mathrm{SL}_G)\)。这里的维度是**分层/比较因素**，不代表每个组合都重新训练一次模型。

## 3. 两个且只有两个性能评价指标

### 3.1 平均运营成本 `AC`：越低越好

设模型给出的需求分位数为 \(\widehat Q_\tau(Z)\in[0,B]\)。部署补充策略为

\[
\boxed{q_{\tau,G}(Z)=\big[\widehat Q_\tau(Z)+G-I\big]_+.}
\]

随机需求发生后的期末库存：

\[
I_{\mathrm{end}}=I+q_{\tau,G}-D.
\]

原论文一般形式为

\[
c_G(q;D,I)=b[G-I_{\mathrm{end}}]_++h[I_{\mathrm{end}}-G]_+,
\qquad \tau=\frac b{b+h}.
\]

Synthetic 采用归一化成本权重

\[
b=\tau,\qquad h=1-\tau,\qquad b+h=1.
\]

因此每个测试日的成本为

\[
\boxed{
c_{\tau,G,t}=
\tau\,[G-(I_t+q_t-D_t)]_+
+(1-\tau)\,[(I_t+q_t-D_t)-G]_+.
}
\]

每次独立测试重复固定包含 \(N_{\mathrm{test}}=3000\) 天。**最终报告平均成本**：

\[
\boxed{
\mathrm{AC}_{\tau,G}^{(r,s)}
=\frac1{3000}\sum_{t=1}^{3000}c_{\tau,G,t}^{(r,s)}.
}
\]

其中 \(r\) 是独立数据重复编号，\(s\) 是训练随机种子（确定性方法无训练种子）。所有方法必须在**同一 3000 个测试日**比较；不能因为模型不同而删除 q=0、低风险或高库存日期。

按照你的最新确认，**正式 P1–P3 结果只展示平均成本 `AC`，不再展示总成本**；两种口径在测试天数相同时排序相同，但平均成本使不同测试规模之间的数值可直接比较。

### 3.2 目标库存服务率 `SL_G`：目标达成频率

\[
\boxed{\mathrm{SL}_G=\Pr(I+q_{\tau,G}(Z)-D\ge G).}
\]

测试集估计：

\[
\boxed{
\widehat{\mathrm{SL}}_{G}^{(r,s)}
=\frac1{3000}\sum_{t=1}^{3000}
\mathbf1\{I_t+q_t-D_t\ge G\}.
}
\]

- 服务率表示**期末库存达到或超过目标 \(G\)** 的频率，值在 \([0,1]\)，出图可换成百分比。
- 即使当天所有需求都被满足，只要期末库存小于 \(G\)，该天仍计为未达到服务目标。
- 即使期末库存远高于 \(G\)，该天仍计为达到服务目标；过量库存由 `AC` 中的超额成本项体现。
- 不使用 `fill_rate`、`demand_fulfillment`、`quantile_coverage` 等指标作为本组三项性能实验的附加评价。

### 3.3 两指标为何必须同时看

由补货公式：

\[
I+q_{\tau,G}-G=\max\{\widehat Q_\tau(Z),I-G\}.
\]

所以

\[
\boxed{
I+q_{\tau,G}-D\ge G
\quad\Longleftrightarrow\quad
D\le\max\{\widehat Q_\tau(Z),I-G\}.
}
\]

对于连续 DGP 的真实 Oracle \(Q_\tau(D\mid Z)\)，在需要正补货的情境中目标达成的条件概率为 \(\tau\)；本来不需要补货的情境中至少为 \(\tau\)。但一般训练模型未必精确校准。

**目标服务率较高并不必然代表平均成本较低**：过度补货可以提高 SL，却抬高目标以上的库存成本。按你的运营目标，解释结果时先看 AC 是否降低，再结合 SL 判断目标达标是否改善或产生权衡。不得因为某个模型 SL 更高就忽略其 AC 上升。

### 3.4 最终性能结果表仅保留两个数值列

```text
scene, tau, G, experiment, method_or_variant, information_level,
replicate_id, train_seed, n_test, AC, SL_G
```

`scene/tau/G/experiment/method/replicate/seed/n_test` 是分组或审计元数据；**P1–P3 的最终性能数值列仅有 `AC`, `SL_G`**。如需模型参数数目、超参数选择、训练耗时等，只保存在**可复现性元数据**中，不能在正文增加“第三个性能指标”。

## 4. 公共数据拆分、训练和比较原则

### 4.1 每个独立数据重复的样本拆分

| 用途 | 样本数 | 规则 |
|---|---:|---|
| 开发训练 | **2,000 天** | 调参/初训，仅真实 \(D\) 标签 |
| 验证 | **500 天** | 按预定验证目标选超参和轮数；不得看测试结果 |
| 独立测试 | **3,000 天** | 冻结模型后仅评 `AC`、`SL_G` |
| 冻结后重训 | **2,500 天** | 合并开发训练 + 验证，按已定超参和轮数从头训练 |

对每个场景、每份独立数据重复，方法必须共享相同的拆分与测试日。目标 \(G\) 不改变数据拆分、标签或重训过程。

**注意**：理论 T1–T3 的训练样本量协议与本节不同；不要将性能实验 500 天验证集擅自引入理论 T1 的横轴 \(T\)。

### 4.2 独立重复和训练随机种子

- **10 份独立数据重复**。
- 每个需要随机训练的方法在每份数据重复内使用 **3 个训练随机种子**；SAA 等确定性算法不伪造三份随机训练。
- 在**同一数据重复内**先对 3 个种子的最终 `AC`、`SL_G` 分别求均值，再以 10 份数据重复为统计单位报告跨重复均值和不确定性。
- 同一数据重复内，所有方法面对同一测试 \(Z,D,I\)；对比采用**配对**设计。
- 独立保存数据随机种子、训练初始化种子、Oracle 数值积分/缓存种子；不得从测试表现中挑选种子。

建议呈现均值及跨 10 份独立数据重复的置信区间，不把 30 次训练种子当成 30 份独立数据集。统计比较可以在内部计算配对 `AC`、`SL_G` 差异的置信区间；它们仍是这两个既定指标的比较，不另立新性能评价指标。

### 4.3 统一模型选择规则与搜索预算

- 主任务每个 \(\tau\) 的 DAT 都单独训练。
- **DAT、DeepQR、Flat-ETO**：学习率 `0.0001/0.0003/0.001` × Batch `32/64/128/256`，共 12 个候选；最多 240 epoch，patience 30。
- **Set-ETO**：Normal 与 HurdleGamma 两个分布族，共享**同一个** 12 候选预算：3 学习率 × Batch `64/128` × 2 分布族。
- **GBQR**：3 学习率 × 2 叶节点设置 × 2 迭代数设置，共 12 个候选。
- **wSAA**：4 个最小叶样本数 × 3 个特征比例，共 12 个候选。
- **LQR**：4 个正则强度候选。
- **Rolling-SAA**：4 个窗口 × 2 个星期筛选方式。
- **SAA**：确定性方法，不为填满搜索预算而伪造超参数候选。

具体网格数值应从原工程的 `configs/synthetic.yaml` 及相应现有模块读取；原上传 MD 未列出所有叶节点数、迭代数、正则值、星期筛选的具体数值，**这里不虚构**。

DAT 按验证 Pinball 损失确定最佳 epoch；外层共同配置按五个主 \(\tau\) 的**平均验证 Pinball**选择。选择规则中的 Pinball 是**训练/验证目标**，不是本次性能结果需要展示的第三个指标。

各方法必须遵守已分配的有效验证预算，不允许某模型因测试表现不好而事后获得额外搜索轮次。冻结配置和轮数后从头用 2,500 天重新训练，再在 3,000 天测试集上计算 `AC` 与 `SL_G`。

## 5. P1：基准模型比较

### 5.1 目标与场景

**问题**：在相同的 Synthetic 需求环境、相同事前信息和尽可能公平的训练协议下，DAT 是否能降低平均运营成本并提高/维持目标库存服务率？

场景：**S1、S2、S3、S4**。对每个场景都考察五个主 \(\tau\) 与五个 \(G\)。

### 5.2 固定的方法清单

| 方法 | 简称/角色 | 需要遵守的关键原则 |
|---|---|---|
| DAT | Full DAT | 最新单层 SA + 单层 CA + Day FFN，潜维 64 |
| Sample Average Approximation | SAA | 用训练样本的经验分布形成基准补货策略；确定性算法 |
| Weighted SAA | wSAA | 依据可见情境进行加权或局部样本选择；使用原协议搜索网格 |
| Rolling SAA | Rolling-SAA | 使用预设窗口与星期筛选作历史式基准；DGP 本身没有真实时间趋势 |
| Flat Estimate-Then-Optimize | Flat-ETO | 显式建模患者订单 PMF 与新增连续余量，再求分位数并优化 |
| Set Estimate-Then-Optimize | Set-ETO | 分布族主比较为 Normal、HurdleGamma；遵守共同搜索预算 |
| Linear Quantile Regression | LQR | 线性条件分位数基准 |
| Gradient-Boosted Quantile Regression | GBQR | 梯度提升分位数基准 |
| Deep Sets Quantile Regression | DeepQR | Deep Sets 分位数基准，与 P2 容量匹配池化诊断区分 |

**不添加**所谓 `Historical Receipt`：完全合成数据中不存在医院真实历史收货策略 \(q_{\mathrm{hist}}\)，不能用人造规则伪装成该基准。

### 5.3 不同方法的训练信息公平性

- 所有正常分位数方法的事前信息不得超出 DGP 明示的 \(A,X\)；实际未来 \(U,J,L,D_{\mathrm{new}}\) 一律不可见。
- **Flat-ETO**：原协议明确允许其使用训练样本的患者级实现结果 \(Y_i\) 作为额外监督；这是信息/监督条件的差异，必须在方法说明中明示，不要声称所有模型训练标签完全相同。
- Flat-ETO 保持患者离散 PMF、对新增连续余量估计条件经验 CDF，再做混合卷积求分位数。不能给它真实 \(U,J\) 或直接提供 oracle 分布参数；不能把其标签取整成另一个需求目标。
- Set-ETO 的主分布族为 **Normal 和 HurdleGamma**；原有离散 Negative Binomial 不能直接用离散似然拟合连续需求 \(D\)。如果日后保留半单位离散/Uniform 平滑后的 NB 组合，必须另列预注册的敏感性实验，不混入主 P1。
- `DeepQR` 必须作为独立模型进入 P1；严格有效参数量接近 \(\pm5\%\) 的 Pooling 模型只作为 P2 的辅助消融，不取代独立 DeepQR 基准。
- 所有方法必须使用其对应的已锁定训练与模型选择协议，不得从测试 `AC`/`SL_G` 反向选择超参。

## 6. P2：DAT 模型结构消融

### 6.1 目标和固定条件

**问题**：在可见信息、训练/评价数据及运营环境不变时，患者 Self-Attention、动态日级 Query 与集合聚合方式分别对 `AC`、`SL_G` 有何贡献？

场景固定为 **S2、S3、S4**；主 \(\tau\)、\(G\) 使用同样网格。各变体除被测试结构外遵守相同训练/调参协议。

### 6.2 五个主消融变体

| 变体键 | 结构改动 | 保留信息/模块 |
|---|---|---|
| `full` | 不作改动 | 完整 SA、动态 CA、日级残差 FFN |
| `no_self_attention` | 将患者 SA 残差分支输出设为 0/替换为恒等通路 | 保留 Patient Encoder、动态 CA、Day Encoder、Day FFN、全部可见 A/X |
| `mean_pool` | 用 Mask 后患者 Memory 的**均匀平均**代替动态 CA 的患者权重聚合 | 保留患者编码、患者 SA、日级残差和 Day FFN |
| `sum_pool` | 用 Mask 后患者 Memory 的**求和**代替动态 CA 的患者权重聚合 | 同上；注意人数规模引起的聚合量纲变化 |
| `no_day_query` | 用**可训练常数 Query**替代依赖 X 的 Query | X 仍经 Day Encoder 和日级残差、Day FFN 进入预测器 |

> **实现细化声明**：原 MD 给出了上述变体名称和信息保留要求，但没有完全列出 Mean/Sum Pool 的每个投影矩阵。为便于代码一致性，本版将 Mean/Sum 定义为**使用相同归一化患者 Memory 与一个可学习的输出投影，将 Cross-Attention 替换为 Mask 后 Mean/Sum 聚合**。该细化不改变输入信息集合；应在第一次正式运行前以模块单元测试锁定。

例如设 \(M_i=\operatorname{LN}_m(E_i)\)，有效 Mask \(m_i\in\{0,1\}\)，则可取

\[
\mathrm{Pool}_{\mathrm{mean}}=W_o\frac{\sum_i m_i M_i}{\sum_i m_i},
\qquad
\mathrm{Pool}_{\mathrm{sum}}=W_o\sum_i m_i M_i.
\]

并分别令 \(v=u+\mathrm{Pool}\)，后面的 Day FFN/Linear/Clip 保持一致。\(W_o\) 的确切参数化应在变体代码中固定；不能边训练边修改。

`no_day_query` 中使用一个可训练常数 \(q_0\) 作为 Cross-Attention Query，**仍然保留 \(u=\phi_{\mathrm{day}}(X)\) 的残差主干**。否则会把“是否动态选择患者”与“能否使用日级状态”混在一起。

### 6.3 容量公平性与信息隔离

- 前三类结构修改不删除患者特征 \(A\)、Day 特征 \(X\) 或库存 \(I\)。
- Mean/Sum Pool、Full DAT 的可训练稠密参数数目可能不完全相同；需在可复现性元数据中记录真实数目。
- 原协议额外要求 **Mean/Sum 与 Full 的容量匹配辅助对照**，以有效结构参数量差不超过 \(5\%\) 为目标。这是对结构效应的稳健性检查；结果仍仅报告 AC 和 SL_G。
- `no_inventory`、`no_planned_use` 属于信息删除而非纯结构消融；不要放在 P2。
- `softplus_beta6` 改变非线性与原理论架构，也不混入 P2 主比较。

### 6.4 P2 最终图与识别边界

`P2_AC_ablation`：横轴变体，纵轴平均运营成本 AC；对每个场景/\(\tau\)/\(G\) 进行配对比较。  
`P2_SL_ablation`：横轴变体，纵轴目标服务率 SL_G；使用同样的测试日及图表分面。

可内部计算相同重复中 Full 与消融版的配对成本差和服务率差来确定区间，但不把它们包装成其他独立的性能评价指标。

解释时必须区分：S3 的同群机制影响**患者条件概率**，S4 才进一步通过 \(U\) 引入给定完整输入后的未观测共变；P2 在 S3 表现改善也不能直接作为临床因果作用的证据。

### 6.5 是否增加双重消融？

之前讨论过 `no_self_attention + no_day_query` 的双重消融；**它不是原始 MD 五个主变体的一部分**。目前主协议仍固定为五组，避免无意扩大规模。如以后正式加入，应单列预注册辅助实验，不与五组主结果混合。

## 7. P3：可见患者信息的运营价值

### 7.1 目标

**问题**：面对相同需求机制，血液中心获得的事前信息从日级情境、群体申请摘要、临床风险摘要逐渐扩展至完整患者级特征时，**平均运营成本**和**目标库存服务率**如何变化？

本组改变的是**信息集合**，而不是 DAT 架构本身。必须在五个级别保持相同 `d_model=64`、相同训练规则和预定**可训练参数总预算**，每级从头训练。

场景使用 **S1–S4**（见 §1 的新增执行约定），主 \(\tau,G\) 网格与 P1 相同。

### 7.2 五级信息阶梯及授权范围

| 等级 | 允许 Day 输入 | 允许 Patient Token | 明确禁止 |
|---|---|---|---|
| **L0** | \(c_1,c_2,I\) | 与真实 \(N\) 无关的固定 Dummy Token | \(N\)、人数比例、任何订单汇总、真实患者 Token 数 |
| **L1** | L0 + \(N/M\)、\(\sum_i u_i/M\)、\(\sum_i v_i/M\) | 同样固定 Dummy Token | 单个患者的 \(u_i,v_i,r_i\)、风险摘要 |
| **L2** | L1 + \(\operatorname{mean}(r_i)\)、\(\operatorname{mean}(r_i^2)\) | 同样固定 Dummy Token | 单个患者特征对应关系 |
| **L3** | L2 的全部日级信息 | 实际有效患者 Token \((u_i,v_i,\text{hidden})\) | 逐患者 \(r_i\)；不可通过其他辅助坐标恢复 \(r_i\) |
| **L4** | 完整八维 X | 完整实际患者 Token \((u_i,v_i,r_i)\) | 无额外隐藏 |

L3 **保留** L2 的临床风险均值和二阶矩，因而 L3→L4 识别的是**逐患者风险与逐患者申请量的对应关系**所带来的额外可用信息，而不是从“没有任何风险信息”到“有风险信息”的差异。

### 7.3 防止人数和风险信息泄漏的强制实现方式

**同一个输入张量结构不等于同一信息集合**。如果 L0–L2 虽然把 \(u_i,v_i,r_i\) 全部设为零，却仍然向模型提供与实际人数 \(N\) 相同的有效 Token 数或真实 Padding Mask，则 Cross-Attention 可以从 Token 数/归一化权重、实现细节或其他路径间接感知 \(N\)。这违反 L0 的信息限制。

因此：

1. L0–L2 使用一个固定有效 Dummy Token（或另一个已核验与真实 \(N\) 完全无关的固定 Token/Mask 模式），不传入真实长度。
2. 8 维 \(X\) 始终有相同的张量长度；未授权坐标使用**固定输入门控屏蔽**，不能在模型内从 `patient_mask.sum()` 重新构造 \(N/M\)。
3. L3/L4 才向模型传入真实患者 Token 与相应 Mask；L3 的 `r` 坐标被固定门控隐藏。
4. 严禁使用排序索引、真实患者 ID、结果 \(Y_i\)、未观测 \(U\) 或标签 \(D\) 的派生值作为隐藏侧信息。
5. 输入门控、Dummy Token 的参数化不得随级别偷偷改变潜维或有效参数预算；所有层级从头训练。
6. 额外做**信息不变性测试**：固定 L0 信息并改变隐藏的患者人数/特征时，L0 模型预测应不变；L1/L2 同理，只允许已授权的摘要变化导致预测变化。

### 7.4 为什么信息更丰富不保证训练结果单调更好？

在理论上，如果 \(\mathcal I_0\subseteq\cdots\subseteq\mathcal I_4\) 是嵌套信息集合，那么在相同运营目标和成本下，最优可行策略集合扩大，使**Bayes 最低运营成本**弱下降。

但对于有限数据、固定容量和有限步优化的五个 DAT，实际 AC 不保证严格单调；更复杂信息可能增加估计/优化难度。SL_G 也不存在必须逐级上升的相同逻辑，因为最小成本决策会权衡目标以上库存的成本。

在本次 P3 中只报告实际训练 DAT 的 **AC 与 SL_G**；不额外计算和报告低信息级别专属的 Bayes oracle 风险作为第三指标。若未来要研究信息的纯 Bayes 价值，应另开理论或补充研究，并对每个信息级别积分掉未观察变量，不能把完整信息 Oracle 直接套给低信息级别。

### 7.5 P3 最终图表

1. `P3_AC_information_ladder`：横轴信息等级 L0–L4，纵轴平均成本 AC，按场景/\(\tau\)/\(G\) 分图，使用跨独立重复区间。
2. `P3_SL_information_ladder`：横轴信息等级 L0–L4，纵轴目标服务率 SL_G，采用相同图表结构。
3. 表格可按 L0–L4 为行，以 `AC` 和 `SL_G` 为两列。相邻等级可配对比较这两个既定指标，不再新增“信息收益百分比”作为主性能指标。

## 8. 统一运行流程与结果生成

### 8.1 数据及模型矩阵

- **P1**：4 场景 × 9 方法 × 5 主 \(\tau\) × 5 个 \(G\) × 10 数据重复。不同 \(G\) 不重新训练；3 种训练 seed 只对随机方法适用。
- **P2**：3 场景 × 5 主变体 × 5 主 \(\tau\) × 5 个 \(G\) × 10 数据重复，额外容量匹配诊断单独标注。
- **P3**：4 场景 × 5 信息层级 × 5 主 \(\tau\) × 5 个 \(G\) × 10 数据重复。

这些是**最终评价组合数量的维度说明**，不是独立模型拟合次数；务必复用同一 \(\tau\) 预测结果在不同 \(G\) 上计算决策成本与目标达标率。

### 8.2 单个性能实验的规范流程

```text
for data_repeat r in 1..10:
    generate shared ex-ante inputs for paired scenarios
    for each scenario authorized for the experiment:
        generate independent train[2000], valid[500], test[3000]
        for each method / DAT variant / information level:
            for each eligible hyperparameter candidate:
                for each main tau:
                    train on train[2000] with real demand labels
                    select epoch by permitted validation training objective
            choose frozen configuration using predeclared validation criterion
            retrain from scratch on train+valid[2500]
            for each permitted training seed:
                predict quantile on the identical test inputs, once per tau
                for each G in [260,280,300,320,340]:
                    q = max(pred_quantile + G - I, 0)
                    end = I + q - D
                    AC = mean(tau*max(G-end,0) + (1-tau)*max(end-G,0))
                    SL_G = mean(end >= G)
                    save only AC, SL_G as final performance outcomes
aggregate training seeds within each data_repeat
aggregate across the 10 independent data_repeat units
```

上述伪代码描述**统计逻辑**；真实实现可以共享多 \(\tau\) 参数化的基准模型，但 DAT 仍然按每个 \(\tau\) 独立训练。普通模型不读取 Oracle 分位数作为训练标签。

### 8.3 对结果矩阵的两项强制自检

1. **固定预测，改变 \(G\)**：同一 \(\tau\)、同一测试数据、同一模型的分位数预测数组不变；只有 \(q\)、期末库存、AC 和 SL_G 会改变。
2. **无结果删选**：当 \(I-G\) 很大时，可能存在无需补货且必然目标达标的日期。这是本 DGP 保留的运营情境。所有 \(G\) 都必须包含原始全部 3,000 个测试日，不能根据 \(q=0\) 或 `SL_G=1` 事后筛选。

### 8.4 可复现运行入口

原实验合同规定：

```bash
python scripts/run_synthetic_experiments.py --family all --smoke --name check
python scripts/run_synthetic_experiments.py --family performance --name performance_main
```

单组通过脚本支持的 `--group` 参数运行，组名以实际 `synthetic/README.md` 为准。

- 正式运行前固定代码 commit、配置 hash、DGP 参数、验证预算、随机种子和指标公式。
- `--resume` 必须验证缓存和已完成文件的配置指纹；不能在代码变化后混合新旧结果。
- 原始样本、模型权重、训练缓存和结果文件只保留本机；Git 仓库仅存放代码和协议。
- Smoke Test 只用于检查流程和耗时，**不能**用于声称 DAT 已优于其他方法。

## 10. 论文撰写时的解释边界

- **P1 只证实或否定模型在合成机制上的运营表现**；不能因优于 SAA 就推断在所有医院环境中占优。
- **P2** 是网络组件的受控结构对照，不等于对真实患者间因果影响的识别；动态注意力收益需从同一测试样本上的 AC/SL_G 体现。
- **P3** 估计的是在给定样本量与架构下**已实现的信息价值**；实际五级曲线不必在成本或服务率上逐级单调。
- **AC 越低越好；SL_G 越高表示越常达到最低目标**。两者可能存在权衡，解释时不能将 SL_G 单独当作唯一最优性标准。
- 本 Synthetic 协议不研究医院历史补货的离线策略评估、真实临床因果效应、跨医院公平性或多血液品类的联合动态分配。

---

**冻结结论**：三组性能实验统一使用原 DGP、原库存尺度、S1–S4 机制、五个主 \(\tau\) 和五个 \(G\)。P1 比模型、P2 比结构、P3 比信息；最终结果始终只展示**平均成本 `AC` 与期末达到目标 \(G\) 的服务率 `SL_G`**。
